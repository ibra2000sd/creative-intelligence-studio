# Command reference

Generated by `node scripts/gen-cli-docs.mjs` from `creative-studio help`. Do not edit by hand.

The command is `creative-studio`. Inside Claude Code it is on the PATH while the plugin is enabled; from a checkout of this repository use `node plugin/bin/creative-studio` or `pnpm cs`.

Most commands accept `--json` for machine-readable output and `--project <dir>` to act on a project other than the current directory.

**Exit codes:** 0 success; 1 failed (a check failed or input was invalid); 2 usage error; 3 blocked by an approval gate, a handoff contract, a policy or a budget; 4 an optional engine is not installed.

## Project

### init

Create a project from a validated client brief.

```text
creative-studio init [dir] --brief <brief.json> [--json]

Validates the brief against the brief contract, creates .cis/ (project, brief,
asset registry, cost ledger, event ledger) and adds secret and cache paths to
.gitignore. Refuses to overwrite an existing project.
Get a starting brief with: creative-studio brief template
```

### doctor

Report engines, tools, credentials and platform limits.

```text
creative-studio doctor [--json]

Checks Node, optional engines (raster, browser, vector, model3d), a Chromium
browser, git/npm/ffmpeg, native mobile toolchains and which image providers
have credentials. Credential values are never printed.
```

### setup

Install the pinned optional engines.

```text
creative-studio setup [--only raster,browser,vector,model3d] [--dry-run]

Installs exact versions from runtime/package.json into the plugin data
directory (or ~/.creative-studio/runtime). This is the only command that
downloads code, and it does so only when you run it.
```

### brief

Validate a brief or print a template.

```text
creative-studio brief check [--file brief.json] [--json]
creative-studio brief template
```

### research

Record and check sourced research findings.

```text
creative-studio research add --topic <audience|competitor|convention|technology|accessibility|legal|content>
                             --kind <fact|inference|client-statement> --finding "..." [--source <url>] [--basis "..."] [--implication "..."]
creative-studio research list | check [--json]

A fact must carry a source URL; an inference must state its basis.
```

### validate

Validate any JSON file against a contract.

```text
creative-studio validate <schema> <file.json> [--json]
```

## Orchestration

### plan

Build the task graph, handoff contracts and approval gates.

```text
creative-studio plan [--replan] [--json]

Classifies the brief and writes .cis/state.json. --replan refreshes the graph
after the brief changes and keeps completed tasks and recorded approvals.
```

### status

Show progress, blockers, gates and the next action.

```text
creative-studio status [--json]
```

### task

Start, complete, fail, reset or recover tasks.

```text
creative-studio task start <id>
creative-studio task done <id> [--evidence path,path]
creative-studio task fail <id> --reason "..."
creative-studio task reset <id> --actor "<human name>"
creative-studio task check <id>
creative-studio task recover

"done" succeeds only when the task's declared outputs exist and validate.
A task that fails three times escalates and waits for a person.
"recover" reconciles state with the files on disk after an interruption.
```

### approve

Record a human decision on an approval gate.

```text
creative-studio approve <gate-id> --actor "<human name>" [--role client|creative-director]
                        [--decision approved|rejected|changes-requested] [--note "..."] [--simulated]

Automated actors (agent, claude, ai, bot, qa ...) are refused. --simulated marks
a demo or benchmark decision and is shown wherever the gate is reported.
```

### route

Show which skills a plain-language request maps to.

```text
creative-studio route "<request>" [--json]
```

### ledger

Show or verify the tamper-evident event ledger.

```text
creative-studio ledger [--last 30] [--json]
creative-studio ledger verify
```

### checkpoint

Snapshot or roll back a deliverable directory.

```text
creative-studio checkpoint create <dir> [--label before-repair]
creative-studio checkpoint list
creative-studio checkpoint restore <id>
```

## Experience DNA

### dna

Check, version, export and compare the Experience DNA.

```text
creative-studio dna check [--json]            schema + semantic lint (contrast, licences, motion sanity, RTL)
creative-studio dna tokens                    write design-system/{tokens.css,tokens.json,theme.ts,scene.json}
creative-studio dna bump --from <file> --reason "..." [--revision-request rev-001]
creative-studio dna approve                   mark approved after gate G2-system has a human decision
creative-studio dna diff <revA> [revB]
creative-studio dna fingerprint [--registry <studio-fingerprints.json>] [--record]
creative-studio dna consistency [--json]      verify every deliverable still matches the DNA
creative-studio dna template
```

### directions

Validate, present and select creative directions.

```text
creative-studio directions check [--json]     contracts, contrast, and pairwise distinctness (>= 3 of 6 axes)
creative-studio directions board              render .cis/reports/directions.html for the client
creative-studio directions select <id> --reason "..."
```

### motion

Decide, route and lint motion.

```text
creative-studio motion decide --surface <marketing|application|mobile|3d> --intent <orientation|feedback|continuity|explanation|storytelling|delight|status>
                              --trigger <load|scroll|hover|press|drag|state-change|route-change|data-update|in-view>
                              --frequency <constant|frequent|occasional|rare|once> [--properties transform,opacity] [--framework react]
creative-studio motion check [--file motion-spec.json] [--json]

"decide" may answer NONE: not animating is a valid, recorded outcome.
```

## Production

### brand

Build the logo system, icons, applications and guidelines.

```text
creative-studio brand build [--json]
creative-studio brand check [--json]

Reads .cis/brand-spec.json and the Experience DNA. Produces editable vector
masters (filled paths, outlined wordmark, no raster), colour / reversed /
one-colour variants, PNG and WebP exports at exact sizes, vector PDFs, an icon
family, applications with print bleed, guidelines (HTML and PDF) and
brand/brand-manifest.json with integrity and completeness checks.
Needs the vector engine; raster and browser engines add PNG/WebP and PDF.
```

### images

Generate, inspect, register and verify visual assets.

```text
creative-studio images providers [--json]          engines, availability and capabilities
creative-studio images estimate [--provider id]    cost estimate against the remaining budget
creative-studio images generate [--provider id] [--brief file] [--consent] [--force] [--json]
creative-studio images verify                      re-hash every registered file
creative-studio images list

Default provider is local-procedural (offline, free, deterministic). Remote
providers are refused when the brief sets externalUploads to "deny", need
--consent when it is "ask", and stop when the project budget would be exceeded.
Each output is checked for exact dimensions, blank renders, palette adherence,
byte budget and near-duplicates before it is registered with provenance.
```

### website

Scaffold or sync the marketing website or web application.

```text
creative-studio website scaffold [--kind marketing|app] [--force]
creative-studio website sync [--kind marketing|app]

scaffold copies the template into web/ (or app/) without overwriting files that
already exist, then generates tokens, fonts, icons and links brand and image
assets. sync refreshes only the generated files after a DNA or asset change.
The marketing site needs .cis/content-web.json (content-web contract).
```

### mobile

Scaffold or sync the Expo mobile application.

```text
creative-studio mobile scaffold [--force]
creative-studio mobile sync

Copies the Expo Router template into mobile/ and generates the theme, icons
and app.json identity from the Experience DNA.
```

### 3d

Build the 3D model, fallbacks and interactive scene.

```text
creative-studio 3d build [--force] [--json]
creative-studio 3d sync
creative-studio 3d stills [--json]

Generates the product GLB from procedural geometry with DNA materials,
optimises it (meshopt), validates source and optimised files with the Khronos
glTF validator, writes drawn still fallbacks per finish and scaffolds scene/.
After the scene is built (npm run build), "stills" replaces the drawn
fallbacks with images rendered from the real model, in light and dark, so the
still and the live view show the same object. Run it again after a DNA change.
```

### preview

Serve a built directory on loopback.

```text
creative-studio preview <dist-dir> [--port 4173] [--spa]
```

## Quality

### test

Run functional, visual, accessibility, motion and performance checks.

```text
creative-studio test [project] [web] [app] [scene] [mobile] [--update-baselines] [--quick] [--max-attempts 3] [--json]

Serves each built deliverable on loopback and checks, at phone, tablet and
desktop sizes: runtime errors, failed requests, broken images, overflow and
clipped text, WCAG 2.2 A/AA rules (axe-core, both colour schemes), keyboard
order and focus visibility, target size, reduced-motion behaviour, lab web
vitals under 4x CPU throttling, scroll frame timing, visual regression against
accepted baselines, and the deliverable's own scripted flows (qa/flows.mjs).
Mobile adds type check, Jest, and iOS/Android production bundles.
Writes .cis/reports/qa-summary.{json,md}, defects.json and screenshots.
A check that cannot run is reported as blocked, never as passed.
```

### audit

Security, privacy, licence and provenance audit with SBOM.

```text
creative-studio audit [--offline] [--json]

Secrets scan, unsafe source patterns, third-party requests in built pages,
CycloneDX SBOM and licence classification per deliverable, known-vulnerability
audit (needs registry access; --offline skips it), ledger and asset-rights checks.
```

### review

Validate an independent creative review against the rubric.

```text
creative-studio review check [--json]
creative-studio review template

A review must be independent, cite the evidence it looked at, discriminate
between criteria and be consistent with its own findings. It is an evaluation,
never client approval.
```

### d2c

Analyse a design reference and diff an implementation against it.

```text
creative-studio d2c analyze <reference.png> [--json]
creative-studio d2c compare <reference.png> <candidate.png> [--out dir] [--threshold 0.03]
creative-studio d2c compare <reference.png> --url <url> [--selector css] [--out dir]

compare renders the implementation at the reference's exact pixel size, reports
the share of differing pixels, names the worst regions on an 8x8 grid and
writes a heatmap, so corrections can be targeted instead of guessed.
```

## Delivery

### revise

Record, scope, verify and close client revision requests.

```text
creative-studio revise add --target <asset|dna|deliverable|direction>:<id> --feedback "..." --change <kind>
                           --by "<who asked>" [--preserve layout,typography,brand_colors,copy,motion,imagery,logo,structure,materials]
creative-studio revise list
creative-studio revise start <id>     snapshot every deliverable file and print the steps for this kind of change
creative-studio revise verify <id>    compare with the snapshot; fail if anything outside the request's scope changed
creative-studio revise close <id> --actor "<name>" [--decline]

Change kinds: color.adjust, typography.adjust, layout.adjust, motion.adjust, copy.edit, asset.regenerate, asset.replace, logo.adjust, scene.adjust, function.fix, scope.add
```

### export

Build the hashed delivery package with evidence and provenance.

```text
creative-studio export [--draft] [--with-evidence] [--json]

A final export requires a non-failing QA summary, human approval of gate
G6-quality, an intact ledger and no simulated or rights-unknown assets.
--draft produces a clearly marked review package that lists every blocker.
Writes export/<project>-...zip, DELIVERY.md and delivery-manifest.json.
```
